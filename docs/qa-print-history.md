# 打印历史与多盘项目验收

本文是 CYLUNE 打印历史、多盘导入和逐盘结算的发布验收清单。自动化测试只能证明数据约束；缩略图观感、深浅色、三套语言和完整用户流程仍需在最终 `发布/CYLUNE.app` 中人工确认。

状态统一使用：`通过`、`失败`、`待验收`。没有在最终打包应用中实际执行的项目不得标为通过。

## 1. 验收边界

- 一个导入文件创建一个打印项目；一个物理盘创建一个独立盘记录和一个独立打印任务。
- 耗材只能逐盘结算，禁止以项目总量一次扣减。
- 文件刚导入、确认颜色映射或切换盘时均不得扣料；只有确认某一盘的打印结果后才写入扣减流水。
- 任一盘已结算后，整个项目不可删除；其余未打印盘只能逐盘跳过，跳过不扣料。
- 撤销使用反向流水恢复余额，不删除既有结算记录。
- 原始 `.3mf` / `.gcode.3mf` 不复制进历史记录；缩略图以独立的内容寻址媒体文件保存。
- 本轮不得改变桌面黑洞的外观与动画；从黑洞导入时应进入与主窗口导入相同的项目流程。

## 2. 测试准备

1. 完全退出开发版、旧版和已挂载镜像中的 CYLUNE，只启动 `发布/CYLUNE.app`，避免出现两个进程、两个菜单栏入口或两只黑洞。
2. 先导出一份本地备份。记录测试所用实体卷的 `spool_id`、初始克数和流水条数。
3. 为测试文件中的每个颜色建立独立实体卷；即使两卷颜色相同，也不得复用同一个卷记录。
4. 准备以下三个只读样本：
   - 单盘：用户提供的 `萨莫面具-布莱克.gcode.3mf`；预期 1 盘、4 色、14 层、18,307 秒，并优先包含彩色模型缩略图候选。
   - 多盘：由 Bambu Studio 导出的至少 2 盘 `.gcode.3mf`，两盘使用量应明显不同，便于核对独立扣减。
   - 无图：有效且已切片，但不含 `Metadata/plate_N.png`、`plate_N_small.png` 和 `plate_no_light_N.png` 的测试 3MF。
5. 不要修改、改名、复制或提交用户提供的真实文件。测试记录只保留文件大小、哈希和解析摘要，不记录到日志或截图中的完整私人路径。
