# 黑洞切片分流与临时产物设计

## 目标

让黑洞成为统一文件入口，并把 CYLUNE 的后台切片限定为“提取打印数据”的内部步骤：普通 3MF 进入切片页，已切片文件进入打印任务；用户不再选择或保留导出的 G-code。

## 文件分流

- 黑洞继续只把用户明确拖入目标区域的普通文件交给 Rust 处理。
- `.3mf` 到达后先按 ZIP 内容判断，而不是依靠文件名：
  - 普通项目 3MF：完成吸入动画，打开主窗口并发送带规范化绝对路径的 `open-slice` 事件。
  - 已切片 `.gcode.3mf`：沿用打印项目导入、重复任务确认和待结算导航。
- 支持的独立 G-code 沿用现有导入规则；缺少必要耗材配置时显示稳定错误。
- 其他文件继续执行吐出动画，不创建切片或打印记录。
- 普通 3MF 不再发送 `pet-import-error: unsliced_project`，因此主窗口不显示“这个项目尚未切片”。

## 临时切片

- 切片页删除“输出位置”和文件保存对话框。
- 前端 `FastSliceRequest` 不再接受用户提供的 `output_path`。
- Rust 为每个任务在应用缓存根目录下创建不可预测且任务独占的目录，Bambu Studio CLI 只向该目录写入 `.gcode.3mf`、日志和辅助文件。
- CLI 退出后，后端按现有安全规则验证 3MF 完整性，再从该临时文件读取每盘重量、时间、层数、颜色和预览图。
- 导入事务成功后写入打印项目、盘、耗材用量和缩略图资源；打印记录采用原始普通 3MF 的文件名和来源路径，不暴露临时文件名。
- 不再把切片结果复制或硬链接到桌面、下载目录或用户选择的位置。

## 持久化与清理

- 永久保留：SQLite 中的打印记录、逐盘指标、逐色耗材数据，以及应用数据目录 `media` 中内容寻址且压缩后的缩略图。
- 自动清理：临时 `.gcode.3mf`、Bambu 日志、原始预览图副本、物化的临时 process/filament 配置和任务目录。
- 成功、失败、用户取消、导入事务失败和 App 下次启动时的孤儿任务扫描都必须收敛到清理逻辑。
- 清理失败不得把已成功导入的记录回滚，但要在后续启动时重试；临时路径永远不写入可恢复的打印记录。

## 界面行为

- 普通 3MF 被黑洞吸入后，主窗口切换到“切片”，自动载入该文件并读取最新打印机列表。
- 用户只需选择打印机、工艺、打印板和耗材预设，然后点击“开始后台切片”。
- 配置阶段保留“取消本次切片”；运行阶段保留“取消切片”。
- 完成后直接打开新生成的打印项目详情，不出现“输出文件已保存”提示。

## 分发约束

- 每台 Mac 使用自己的本地数据库、缓存和权限，不会携带开发者机器上的库存。
- 后台切片依赖对方已安装兼容版本的 Bambu Studio 及其官方配置。
- 黑洞真实扭曲模式首次开启需要对方授予屏幕录制权限；拒绝权限不影响主窗口、耗材库和切片核心。
- 当前发布物为 arm64，仅支持 Apple Silicon。Intel Mac 需要单独的 x86_64 包或后续 Universal 2 构建。
- 当前使用临时本地签名且未公证，外发时可能被 Gatekeeper 阻止；正式公开分发需要 Developer ID 签名和 Apple 公证。

## 测试与验收

- Rust：普通 3MF 黑洞投递产生切片导航而不创建打印任务；已切片文件仍正常导入；无效文件仍吐出。
- React：收到黑洞切片事件后切换页面并载入路径；切片表单不包含输出位置；请求不包含输出路径。
- Rust：成功导入后任务目录和临时 G-code 消失，缩略图资源及数据库记录仍可读取。
- Rust：失败与取消后同样无临时残留，且不会创建半成品打印项目。
- 真实样例：单盘与四盘项目继续得到与 Bambu Studio 一致的重量、层数和模型时间。
