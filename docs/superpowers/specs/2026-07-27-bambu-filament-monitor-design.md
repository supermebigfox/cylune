# 拓竹耗材管家开发设计文档

## 1. 产品概述

“拓竹耗材管家”是一套面向拓竹 A1 + AMS Lite 的耗材库存工具，由桌面 App 和网页仪表盘组成。

桌面 App 负责读取 Bambu Studio 生成的 3MF/G-code、计算分色耗材、记录打印结果和维护离线数据。网页端负责跨设备查看库存、历史记录、低库存提醒以及管理已绑定设备。

产品不直接连接打印机，不调用未经授权的拓竹云接口，不要求开启 LAN Only 或 Developer Mode，因此不影响 Bambu Handy、MakerWorld 云打印和用户现有的拓竹工作流。

## 2. 第一版目标

- 先交付可安装的 macOS App；
- 桌面代码结构同时兼容后续 Windows 构建；
- 提供需要登录的响应式网页仪表盘；
- 支持一台 A1 和一套四槽 AMS Lite；
- 自动解析本地切片文件的分色耗材与换色消耗；
- 管理不限数量的独立耗材卷，AMS Lite 四槽只表示当前装载状态；
- 成功任务全额结算，失败或取消任务按停止位置结算；
- App 离线可用，联网后与网页自动同步；
- 模型、3MF 和 G-code 始终保留在本地。

## 3. 非目标

第一版不包含：

- 打印机远程控制；
- 拓竹账号或云接口模拟；
- 自动识别完全由 Handy/MakerWorld 发起且本机没有切片文件的任务；
- 多用户协作和角色权限；
- 多打印机管理；
- 短信或邮件提醒；
- App Store 或 Microsoft Store 上架；
- Apple 正式签名、公证和 Windows 代码签名。

## 4. 总体架构

系统由四个边界清晰的模块组成：

1. **桌面壳层**：使用 Tauri 构建 macOS/Windows 桌面应用，负责菜单栏、文件选择、文件夹监听、系统通知和安全凭据存储。
2. **本地核心**：负责 3MF/G-code 流式解析、任务结算、本地数据库、离线同步队列和备份恢复。
3. **云端服务**：负责账号、设备配对、同步事件、网页查询和服务器端去重。
4. **网页仪表盘**：负责登录后查看库存、历史、提醒、设备状态，并可执行换卷、校准、修正和撤销。

桌面端与网页端共享视觉组件、字段定义和校验规则，但桌面端独有文件系统与本地数据库能力。

## 5. 技术选型

### 5.1 桌面端

- Tauri：桌面容器与系统能力；
- Rust：文件监听、ZIP/3MF 流式读取、G-code 解析、SQLite 和同步队列；
- React + TypeScript：桌面界面；
- SQLite：本地持久化；
- macOS Keychain / Windows Credential Manager：同步令牌存储；
- 原生系统通知：待结算与低库存提醒。

选择 Tauri 而不是 Electron，以降低安装体积和常驻内存，并复用 macOS/Windows 核心代码。

### 5.2 网页与云端

- Sites 项目结构与托管；
- React + TypeScript：响应式网页；
- D1：账号、设备、库存流水和同步游标；
- Worker API：登录、设备配对、事件上传与增量拉取；
- 基于安全 Cookie 的网页会话；
- Argon2id 或运行环境支持的等价强密码哈希；
- CSRF 防护、登录限速和设备令牌撤销。

## 6. 用户流程

### 6.1 初次设置

1. 用户在网页注册邮箱和密码并登录。
2. 网页生成短时有效、仅能使用一次的设备配对码。
3. 用户在 Mac App 输入配对码。
4. 云端签发设备令牌；App 将令牌保存到 macOS Keychain。
5. 用户选择一个“耗材监控”文件夹，并设置四个 AMS Lite 槽位。

### 6.2 添加打印任务

1. 用户在 Bambu Studio 切片并将 3MF 或切片文件保存到监控文件夹，或手动拖入 App。
2. App 检测新文件并在本地完成解析。
3. App 展示任务名称、材料、颜色、槽位、模型用量、冲刷/擦料塔用量和总用量。
4. 用户确认槽位映射后，任务进入“等待结算”。
5. 用户继续使用 Bambu Studio、Handy 或 MakerWorld 的官方流程发起打印。

### 6.3 结算任务

- **成功**：按完整 G-code 的分色用量扣减。
- **失败/取消且知道停止层数**：累计截至该层的各工具挤出量并扣减。
- **仅知道进度百分比**：按文件位置和层级信息生成估算，明确标记“估算”。
- **信息不足**：任务保留为“待确认”，不修改库存。

桌面菜单栏和主界面都提供“成功、失败、取消”入口。结算完成后立即写入本地流水，并在联网时同步。

### 6.4 换卷与校准

用户可以在 App 或网页中：

- 为任一槽位安装新耗材卷；
- 设置材料、颜色、品牌、初始净重和空盘重量备注；
- 使用称重值校准当前余量；
- 设置每卷低库存阈值；
- 修正或撤销错误扣减。

所有操作写入审计流水，不直接覆盖历史。

### 6.5 耗材库与槽位

耗材卷是独立库存实体，颜色只是耗材卷的一个属性。即使品牌、材料和颜色完全相同，两卷耗材也必须拥有不同的 `spool_id`、独立余额和独立流水。

耗材库不限制卷数。每卷记录自定义名称、品牌、材料、颜色、批次备注、初始净重、当前估算余量、材料密度、存放位置和状态。默认显示名称可以是“黑色 PLA #001”，用户可自行修改。

AMS Lite 的四个槽位只保存“当前装载了哪一卷”的映射，不代表整个库存：

- 装入：从耗材库选择一卷并绑定到指定槽位；
- 拆下：解除槽位绑定，耗材卷回到“库中”状态，剩余量保持不变；
- 换卷：在一个事务中拆下旧卷并装入新卷；
- 调槽：同一卷可从一个槽位移动到另一个槽位；
- 用完：余额归零并标记“已用完”，保留历史；
- 归档：不再使用的卷从默认列表隐藏，但不删除流水。

打印任务在进入“等待结算”时保存槽位映射快照，结算始终扣减具体 `spool_id`，不能只按颜色扣减。如果切片后换过卷，结算前必须让用户确认实际使用的耗材卷。

拆下未用完的卷时可以直接保留系统估算值，也可以输入称重结果进行校准。重新装回后从该卷最后余额继续扣减。

### 6.6 原厂耗材自动识别

第一版内置拓竹原厂耗材目录，并优先支持 Bambu Studio 切片文件中出现的原厂预设。识别字段包括：

- 品牌：Bambu Lab；
- 基础材质：PLA、PETG 等；
- 产品系列/表面效果：Basic、Matte、Silk、HF 等；
- 预设名称和预设 ID；
- 切片时选择的颜色值；
- 线材直径与材料密度。

AMS Lite 通过 RFID 识别原厂耗材并同步给 Bambu Studio 后，用户仍按官方流程完成切片。App 不直接访问 AMS 或 RFID，而是读取已切片 3MF 中实际用于该任务的耗材配置。因此 App 能自动识别“本次切片使用了 Bambu PLA Basic 黑色”等信息，但不宣称实时读取当前 AMS 内容。

自动匹配按以下规则执行：

1. 使用预设 ID、系列、材质和颜色匹配耗材库；
2. 只有一个可用实体卷匹配时，建议绑定该卷；
3. 没有匹配卷时，提供“一键新建原厂卷”，并自动填写品牌、材质、系列、颜色、密度和默认净重；
4. 有两卷或更多同款同色卷时，必须让用户选择具体卷号，不能根据颜色自动合并；
5. 文件信息与耗材库冲突时，结算前显示差异并要求确认。

切片文件通常不提供可供本 App 稳定依赖的实体卷唯一 RFID 标识，因此实体卷身份以本系统的 `spool_id` 为准。

副厂耗材作为后续扩展：用户手工选择或创建厂家、基础材质、系列/效果和颜色；创建后可复用为自定义预设。数据模型从第一版开始保留这些字段，避免后期迁移。

### 6.7 Handy/MakerWorld 手机任务

完全由 Bambu Handy 或 MakerWorld 发起的任务可能没有出现在电脑本地。Handy 不提供每种颜色的实际用量，网页也不能读取 Handy、AMS、打印机或拓竹云端数据。App 和网页不调用未经授权的拓竹云接口，因此第一版不能自动发现或精确结算没有本地切片文件的手机任务。

手机任务只有以下可验证路径：

1. 用户在打印前或打印后取得同一板件的已切片 3MF，并导入 Mac App；
2. 或者用户在网页选择该 3MF；文件只在浏览器本地解析，云端仍不接收模型；
3. 解析后由用户确认实际使用的四槽实体卷，再按成功、失败或取消规则结算；
4. 没有 3MF 时不创建分色消耗，不允许用总百分比冒充分色克数；
5. 用户只能通过逐卷称重执行库存校准，校准记录标记为“称重修正”，不伪装成打印消耗。

网页可以记录一个不影响库存的“手机任务占位”，提醒用户稍后补充 3MF。截图识别不纳入设计，因为 Handy 页面没有足够的分色用量数据，OCR 也无法补出不存在的信息。

## 7. 3MF 与 G-code 解析

### 7.1 输入

- Bambu Studio 导出的已切片 3MF；
- 独立 G-code 文件；
- 未包含切片数据的项目文件应提示用户先完成切片。

### 7.2 解析策略

- 3MF 作为 ZIP 容器读取；
- 仅打开计算所需的元数据和 G-code 条目；
- G-code 按行流式处理，不把完整文件放入内存；
- 跟踪绝对/相对挤出模式、工具切换、重置挤出轴和层标记；
- 对每个工具累计正向净挤出长度；
- 使用线材直径与材料密度换算克数；
- 将已存在于 G-code 中的冲刷、引流和擦料塔挤出计入对应工具；
- 保存解析器版本与源文件哈希，以便重算和防止重复导入。

### 7.3 材料密度

优先读取切片配置中的密度。缺失时使用内置材料默认值并标记为估算。用户校准材料密度后，新任务使用新值，历史任务保持原结算快照，除非用户主动重算。

### 7.4 大文件约束

解析器内存使用必须与文件大小基本无关。测试目标是在 512MB 可用内存限制下解析大型多色 3MF，以保证低配 Windows 设备也可运行。

## 8. 数据模型

### 8.1 核心实体

- `users`：账号、密码哈希、状态和时间戳；
- `web_sessions`：网页会话与过期时间；
- `recovery_codes`：仅在注册时展示、服务器只保存哈希的一次性恢复码；
- `devices`：设备名称、平台、版本、最后同步时间和撤销状态；
- `filament_catalog`：品牌、基础材质、产品系列/效果、官方预设 ID、颜色和默认物性；
- `spools`：独立卷 ID、目录条目或自定义预设、自定义名称、材料、系列、颜色、品牌、批次、初始净重、当前状态、存放位置、密度和阈值；
- `ams_slots`：四个槽位与当前独立耗材卷的映射；一个槽位最多一卷，同一卷最多占用一个槽位；
- `print_jobs`：文件哈希、任务状态、结算方式、置信度和解析器版本；
- `job_consumption`：按任务、工具、槽位和耗材卷记录的计划/实际克数；
- `ledger_events`：不可变库存流水；
- `sync_events`：用于多端增量同步的事件封装；
- `pairing_codes`：短时、一次性设备配对码。

### 8.2 库存计算

库存不以可被两端覆盖的单个数字为事实来源。每次换卷、消耗、校准、修正和撤销都写入不可变流水，当前余额由流水汇总得到，并保存可重建的查询缓存。

## 9. 同步协议

### 9.1 本地优先

每次操作先在 SQLite 事务中写入业务数据和 `outbox`。用户无需等待网络即可继续操作。

### 9.2 上传

App 使用设备令牌通过 HTTPS 批量上传事件。每个事件包含：

- 全局唯一事件 ID；
- 用户、设备和本地递增序号；
- 事件类型和结构化载荷；
- 客户端时间与协议版本。

服务器以事件 ID 和设备序号去重，重复重试不会重复扣减。

### 9.3 下载

客户端保存服务器游标，只拉取游标之后的事件。应用事件成功后推进游标；中途中断可安全重放。

### 9.4 冲突规则

- 库存变化以追加流水合并，不执行余额覆盖；
- 同一打印任务只能存在一个有效结算版本；修正通过反向流水和新版本实现；
- 槽位映射按服务器事件顺序生效，并在 UI 中显示变更来源；
- 耗材名称等展示字段使用版本号进行乐观并发控制；
- 无法自动合并的冲突进入“需要处理”，不静默丢弃数据。

## 10. 登录、配对与安全

### 10.1 网页账号

- 第一版使用邮箱和密码；
- 密码只保存强哈希，不保存明文；
- 登录接口限速并记录安全事件；
- 会话 Cookie 设置 `HttpOnly`、`Secure` 和合适的 `SameSite`；
- 第一版不发送找回邮件；注册时生成一次性恢复码，用户可用未使用的恢复码重设密码；

### 10.2 设备配对

- 配对码短时有效、一次性使用且与当前登录用户绑定；
- 成功配对后只返回设备令牌，不向 App 返回密码；
- 设备令牌可在网页单独撤销；
- macOS 使用 Keychain，Windows 使用 Credential Manager；
- 令牌不写入普通配置文件、日志或备份。

### 10.3 隐私边界

云端允许接收：任务名称、文件哈希、时间、材料、颜色、克数、状态、槽位和诊断摘要。

云端禁止接收：3MF、G-code、模型网格、模型缩略图、拓竹账号凭据和打印机访问码。

## 12. 网页端界面

- 登录和退出；
- 与桌面端一致的库存首页；
- 打印历史和耗材流水；
- 手机任务占位、浏览器本地 3MF 解析和补充结算；
- 换卷、校准、修正和撤销；
- 已绑定设备列表、最后在线时间和撤销按钮；
- 响应式手机布局；
- 网页端不提供本地文件夹监听。

## 13. 离线、备份与恢复

- App 启动后先打开本地数据库，不依赖云端可用性；
- 失败上传使用指数退避并保留在 outbox；
- UI 明确区分“已保存到本机”和“已同步”；
- 导出包包含本地业务数据、未完成任务和非敏感配置；
- 导出包不包含设备令牌和账号密码；
- 导入前创建本地备份，并通过事件 ID 去重。

## 14. 错误处理

- 文件仍在写入：等待文件大小稳定后解析；
- 文件损坏或未切片：显示可执行的错误说明，不创建扣减；
- 未知 G-code 方言：停止自动结算并保留诊断摘要；
- 槽位映射缺失：要求用户确认；
- 重复文件：复用已有解析结果并询问是否为新打印；
- 同色卷混淆：结算绑定具体耗材卷 ID；无法确认实际使用卷时暂停扣减；
- 原厂预设无法识别：保留文件原始字段并要求用户确认，不错误归类为其他系列；
- 手机任务没有 3MF：不生成分色消耗，只允许创建占位或逐卷称重校准；
- 网络失败：保留本地数据并后台重试；
- 登录过期：暂停同步，不影响本地功能；
- 设备令牌被撤销：清除安全凭据并要求重新配对；
- 同步冲突：进入待处理列表，不覆盖用户数据。

## 15. 测试策略

### 15.1 解析器

- 单色、多色、频繁换色和擦料塔样本；
- 绝对/相对挤出、`G92 E0`、回抽和工具切换；
- 成功、指定停止层和百分比估算；
- 损坏 ZIP、缺失 G-code 和未知材料；
- 大文件内存与耗时基准；
- 黄金样本与 Bambu Studio 显示用量对比。

### 15.2 本地数据

- SQLite 迁移、事务回滚和崩溃恢复；
- 重复导入和重复结算；
- 修正与撤销后的流水守恒；
- 备份导出与恢复。

### 15.3 同步

- 离线新增后恢复网络；
- 重试、乱序、重复和部分批次失败；
- 两端同时换卷或修正；
- 令牌过期与撤销；
- 游标重放和服务器去重。

## 17. 第一版验收标准

1. 在 macOS 上安装并启动 App，无需 Docker、Java 或浏览器插件。
2. 导入已切片多色 3MF 后，按颜色展示模型、冲刷和总耗材。
3. 成功任务可全额扣减；失败任务可按停止层计算；百分比路径明确标记估算。
4. 耗材库可保存不限数量的独立卷；相同颜色的两卷拥有不同余额和流水。
5. 原厂切片配置可识别品牌、PLA/PETG 等基础材质、Basic/Matte/Silk 等系列和颜色；同款多卷仍要求选择实体卷。
6. 手机任务没有 3MF 时不扣减分色库存；补充同一板件的已切片 3MF 后才能结算。
7. 四槽装入、拆下、换卷、调槽、校准、低库存、修正和撤销均产生可审计流水。
8. 断网时所有本地功能可用，联网后不重复同步。
9. 网页需要登录，且只能查看当前账号的数据。
10. App 可通过一次性配对码绑定，网页可撤销设备。
11. App 与网页的新增和修正可双向同步且不覆盖历史。
12. 网络请求与云端数据库中不存在 3MF、G-code、模型几何或拓竹凭据。
13. 代码结构可在不重写解析器、数据模型和主要界面的前提下增加 Windows 构建。
