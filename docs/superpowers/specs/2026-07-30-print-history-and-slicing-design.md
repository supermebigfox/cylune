# CYLUNE 打印记录与后台切片设计

日期：2026-07-30

## 1. 目标

本轮为 CYLUNE 增加两个相互连接的能力：

1. 将导入的切片任务保存为可浏览的打印记录，按项目和盘面展示缩略图、时间、层数、耗材和结算结果。
2. 接收普通项目 `.3mf`，在不打开 Bambu Studio 主窗口的情况下调用本机 Bambu Studio 命令行完成切片，再将输出作为打印任务导入。

本轮首先交付 macOS 本地版，同时保持数据模型和切片适配器可扩展到 Windows。现有库存、AMS Lite 槽位、结算流水、黑洞导入和三语言能力必须继续工作。

## 2. 范围边界

### 2.1 本轮包含

- 项目级打印记录列表和盘面详情。
- 单盘及多盘 `.gcode.3mf` 解析。
- 3MF 内置项目封面和盘面缩略图提取。
- 每盘预计时间、层数和各工具耗材克数。
- 每盘独立映射实体卷、结算和反向流水。
- 本地打印机库，支持多个拓竹打印机和默认打印机。
- 后台调用已安装的 Bambu Studio CLI 切片普通 `.3mf`。
- 快速切片设置、进度、取消和失败恢复。
- 简体中文、繁体中文、英语及明暗主题。
- 数据库和备份格式的兼容迁移。

### 2.2 本轮不包含

- 自研或内嵌完整切片引擎。
- Bambu Handy、MakerWorld 或打印机云任务抓取。
- 直接向打印机发起云打印。
- 在网页服务器执行切片。
- 在 CYLUNE 内复刻 Bambu Studio 的全部高级参数。
- 账号、认证和云同步服务；本轮只为未来同步保留稳定的设备数据结构。
- 在打印记录中展示或保存 Bambu Studio 版本和完整切片参数快照。

## 3. 核心产品模型

### 3.1 项目、盘面与打印任务

三层对象各自承担一种职责：

- `PrintProject`：一次导入或一次重新打印批次，是历史列表中的一张项目卡片。
- `PrintPlate`：项目中的一张物理盘，保存盘号、缩略图和切片统计。
- `PrintJob`：某张盘的一次实际打印尝试，负责耗材映射、结果和结算流水。

一个多盘项目在列表中只出现一次；详情页显示“第 1 盘、第 2 盘……”的盘面卡片。每盘分别打印、分别成功或失败、分别扣减耗材。

重复导入相同文件时：

- 如果存在同一批次的未结算盘面，优先继续原批次。
- 如果上一批次已开始结算，要求用户明确创建新的打印批次。
- 新批次复用内容寻址的解析缓存和缩略图，不重复解析或复制资源。

### 3.2 状态语义

盘面任务状态包括：

- `pending_mapping`：等待选择实体耗材卷。
- `ready`：映射已确认，等待结算。
- `success`：完整打印成功。
- `failed`：指定层停止的失败打印。
- `cancelled`：指定层停止的打印中途取消。
- `estimated`：按百分比估算结算。
- `skipped`：多盘项目中用户决定不打印的一盘，不产生扣减。

“取消此次导入”和“打印中途取消”含义不同：

- 在任何盘都未结算前，“取消此次导入”删除整个批次及其未结算任务，不进入历史，也不改变库存；内容解析缓存可以保留。
- 一旦任意盘已经结算，项目必须保留为历史；其余未打印盘只能标为 `skipped`，不能删除已发生的流水。
- “打印中途取消”是打印结果，按停止层结算实际用量并保留记录。

## 4. 数据模型与迁移

### 4.1 新表

`print_projects`

- `project_id`：UUID 主键。
- `source_hash`：输入文件内容哈希。
- `source_file_name`：用户看到的文件名。
- `source_path`：可为空的外部文件路径引用，不复制源文件。
- `imported_at`：录入时间。
- `plate_count`：有效盘数。
- `cover_asset_id`：可为空的封面资源。

`print_plates`

- `plate_id`：UUID 主键。
- `project_id`：所属项目。
- `plate_index`：从 1 开始的盘号，在项目内唯一。
- `display_name`：盘面显示名；缺失时显示“第 N 盘”。
- `thumbnail_asset_id`：可为空的盘面缩略图。
- `estimated_seconds`：预计总打印秒数。
- `max_layer`：总层数。
- `parsed_json`：该盘稳定的解析结果，包含工具、材料资料和逐层累计用量。

`media_assets`

- `asset_id`：内容哈希主键。
- `relative_path`：应用数据目录内的相对路径。
- `mime_type`、`width`、`height`、`byte_size`。
- 同一图片只保存一份。

`printers`

- `printer_id`：本地 UUID。
- `display_name`：用户命名。
- `model_key`：Bambu Studio 官方机型标识。
- `nozzle_diameter`：喷嘴直径。
- `default_plate`：默认打印板标识。
- `ams_kind`：无 AMS、AMS Lite、AMS 或其他官方类型。
- `is_default`：本机唯一默认设备。
- `created_at`、`updated_at`。

### 4.2 现有表调整

- `print_jobs` 增加可空 `plate_id`，新记录必须关联盘面。
- `parse_cache.parsed_json` 升级为版本化的多盘结构 `ParsedProjectV2`。
- 旧版单盘缓存按 `ParsedProjectV1` 兼容读取，并在首次使用时作为第 1 盘懒迁移；不要求破坏性重写。
- 旧 `print_jobs` 在迁移时为每个来源生成一个兼容项目和第 1 盘，保留原 job ID、映射、消费记录和流水引用。
- 数据库迁移必须单事务执行；任一步失败时回滚到旧结构。

### 4.3 媒体存储

- 图片保存在应用数据目录的 `media/<前两位哈希>/<完整哈希>.<扩展名>`。
- 优先提取 `Metadata/plate_N.png` 作为盘面缩略图。
- 项目封面优先使用 `Auxiliaries/.thumbnails/thumbnail_middle.png`，不存在时使用第 1 盘图片。
- 同时保留图片的原始宽高，界面按需缩放，不在数据库保存大 BLOB。
- 没有内置图片时不渲染模型，使用 CYLUNE 统一占位图。
- 打印记录不复制用户的原始 `.3mf` 或 `.gcode.3mf`。

## 5. 多盘解析

### 5.1 盘面发现

解析器枚举压缩包中的所有 `Metadata/plate_N.gcode`，按数值盘号排序，不再取第一个 `.gcode`。

每盘关联：

- `Metadata/plate_N.json`
- `Metadata/plate_N.png`
- `Metadata/plate_N_small.png`
- `Metadata/plate_no_light_N.png`
- `Metadata/slice_info.config` 中对应 `index=N` 的 `<plate>`

空盘、缺失 G-code 的盘或被切片器标记为不可打印的盘不会创建任务，但会在导入摘要中说明被跳过的原因。

### 5.2 元数据来源

- 打印时长优先读取 `slice_info.config` 的 `prediction` 秒数；缺失时解析 G-code 的 `total estimated time` 注释。
- 层数使用 G-code 层标记解析结果，并与 G-code 的 `total layer number` 交叉校验。
- 耗材扣减克数继续以 G-code 实际正向挤出累计量计算，因此包含换色、冲刷等真实路径消耗。
- `slice_info.config` 中的 `used_g` 只用于校验和展示诊断，不替代库存扣减数据。
- 工具颜色和材料来自盘面配置、项目耗材配置与 G-code 工具编号的组合；映射不完整时要求用户确认。

### 5.3 解析结果契约

解析层输出 `ParsedProjectV2 { plates: Vec<ParsedPlate> }`。每个 `ParsedPlate` 独立拥有：

- 盘号和显示名。
- 预计秒数、最大层数。
- 缩略图候选条目。
- 工具耗材配置。
- 工具总用量及逐层累计用量。

库存匹配、结算和失败层估算只接收单个 `ParsedPlate`，不需要理解压缩包结构。

## 6. 打印记录界面

### 6.1 任务页分区

“打印任务”页面分为：

- `待处理`：仍需要映射、结算或跳过的盘。
- `打印记录`：已经产生打印结果的项目。

历史项目卡片显示：

- 彩色封面。
- 项目名称和录入时间。
- 单盘或“共 N 盘”。
- 项目总预计时间。
- 已完成盘数及状态摘要。
- 预计耗材总克数。

### 6.2 项目详情

项目详情顶部显示项目封面、名称、录入时间和总体进度。下方按盘面展示卡片，卡片包含：

- 彩色盘面缩略图。
- 盘号或盘名。
- 预计打印时间和层数。
- 各色圆点、材质系列及预计扣减克数。
- 当前状态。

点击盘面进入现有映射与结算工作区。结算后显示实际扣减克数，并保留“撤销本次扣减”。

### 6.3 视觉与无障碍

- 延续现有圆润、多巴胺、留白充足的 CYLUNE 视觉，不采用密集工业表格。
- 多盘封面使用轻微叠层表现，但所有核心信息仍有文字，不能只依赖颜色。
- 列表和详情完整支持键盘操作、可见焦点和读屏标签。
- 简中、繁中、英语文案同步交付；日期和时长按当前语言格式化。

## 7. 打印机库

### 7.1 本地设备

用户可以添加多台拓竹打印机并指定一台默认设备。CYLUNE 从已安装的 Bambu Studio 资源目录读取官方机型、喷嘴、打印板、工艺和耗材预设，不内置一套容易过期的复制品。

首次使用切片时：

1. 定位 Bambu Studio 安装目录。
2. 扫描官方打印机预设。
3. 用户选择自己的机型、喷嘴和 AMS 类型。
4. 用户可以将设备命名为“我的 P2S”等，并设为默认。

找不到某个本地已保存机型时，设备保留但标记为“当前 Bambu Studio 未提供该预设”，禁止静默使用其他机型替代。

### 7.2 未来同步边界

`printers` 表使用稳定字段，未来账号同步只同步设备选择和用户命名，不上传 Bambu Studio 本地配置文件。真正切片始终使用当前电脑安装的官方预设。

## 8. 后台切片

### 8.1 选定方案

采用“调用已安装的 Bambu Studio CLI”方案：

- 不自研切片算法。
- 不把完整 Bambu Studio 引擎打进 CYLUNE 安装包。
- 正常切片不打开 Bambu Studio GUI。
- 后台进程可能在活动监视器中短暂可见。

弃用的替代方案：

- 自研切片器：风险、周期和打印安全成本不可接受。
- 内嵌 Bambu Studio/OrcaSlicer 引擎：安装包、许可证合规和版本维护成本过高，不适合首版。

### 8.2 快速切片流程

1. 用户拖入或选择普通 `.3mf`。
2. CYLUNE 识别项目盘数和嵌入配置。
3. 如果嵌入机型与目标打印机一致且配置完整，默认沿用并展示摘要。
4. 如果机型不匹配或配置缺失，要求用户选择打印机、喷嘴、打印板和快速设置。
5. 快速设置只包含层高预设、填充率、支撑和各工具耗材。
6. 用户选择输出位置；默认建议源文件目录，文件名以 `.gcode.3mf` 结尾。CYLUNE 不在记录目录额外复制该输出。
7. 后台执行 Bambu Studio CLI，对全部有效盘执行切片并导出 3MF。
8. 输出稳定且校验成功后，使用同一多盘解析器导入项目记录。
9. 用户可以在 Finder 中显示输出文件。

高级参数不在 CYLUNE 内复刻。用户点击“使用 Bambu Studio 调整”后才启动 GUI；用户保存项目后可回到 CYLUNE 再次静默切片。

### 8.3 进度与进程边界

- 切片由独立的 `SlicerAdapter` 管理，业务层不拼接 shell 字符串，只传递参数数组。
- 优先使用 Bambu Studio 的进度管道；无法获取精确百分比时显示明确的阶段型进度，不伪造数值。
- 临时文件放在一次性任务目录，输出先写临时名称，成功后原子移动到用户选择的位置。
- 不自动覆盖已有文件；同名时要求重新命名或确认覆盖。
- 用户取消或退出应用时终止该切片进程并清理未完成的临时文件。
- 只有输出文件完整、可重新打开且包含至少一个有效盘时才创建打印项目。

## 9. 错误处理

- 未安装 Bambu Studio：解释依赖并提供官方安装入口，不改变输入文件。
- CLI 版本不支持所需参数：显示兼容错误，不尝试猜测参数。
- 文件机型与目标机型不一致：必须显式选择目标打印机并重新切片。
- 缺少打印板、喷嘴、工艺或耗材预设：指出缺少的项目，禁止开始切片。
- CLI 异常退出或崩溃：保留简化后的本地诊断日志，提供“使用 Bambu Studio 打开”，不创建记录。
- 单个盘不可切片：在开始前列出；切片器允许跳过空盘时继续其他盘。
- 输出路径不可写或磁盘空间不足：在启动切片前阻止并提示。
- 源文件在解析或切片过程中变化：使用现有稳定性检查拒绝结果。
- 缩略图损坏：任务数据仍可导入，使用占位图。
- 数据库或图片写入失败：项目、盘面、任务和媒体引用在同一事务语义下回滚；不会出现半条历史记录。

## 10. 安全与隐私

- 输入文件、缩略图、打印记录和切片输出默认只留在本机。
- CLI 参数使用结构化进程参数，不经过 shell，避免文件名被当作命令执行。
- 只接受普通文件，拒绝目录和符号链接沿用现有规则。
- 所有归档条目路径先标准化，拒绝 `..`、绝对路径和越界写入。
- 历史记录保存外部路径引用时允许文件后来被移动；详情仍可使用已提取缩略图和元数据。

## 11. 备份

- 备份包含打印项目、盘面、任务、耗材映射、结算和打印机库。
- 媒体图片以内容寻址资源随备份导出，恢复时验证哈希。
- 不备份原始 `.3mf`、生成的 `.gcode.3mf` 或 Bambu Studio 配置文件。
- 旧版备份仍可恢复；缺少项目层级的旧任务自动作为单盘项目导入。

## 12. 测试策略

### 12.1 解析器

- 单盘真实结构：缩略图、预计秒数、层数、四色和克数。
- 合成多盘夹具：按数值盘号排序并正确关联图片、配置和 G-code。
- 空盘、缺图、损坏图、缺时长、盘号不连续。
- 路径穿越归档条目被拒绝。
- 旧版单盘缓存可以懒迁移。

### 12.2 数据库与库存

- 旧数据库升级后库存、AMS 槽位、不可变流水和历史结算保持一致。
- 多盘分别结算，只扣当前盘映射的实体卷。
- 整批取消在未结算时无库存变化。
- 任一盘结算后禁止整批删除，跳过其他盘不扣减。
- 重复导入复用缓存但创建用户确认的新批次。

### 12.3 切片适配器

- 使用受控的假 CLI 测试参数、进度、成功输出、取消、崩溃和超时。
- 不依赖真实 Bambu Studio 完成自动化单元测试。
- 在本机发布前使用已安装 Bambu Studio 做一项普通 3MF 冒烟测试。

### 12.4 界面

- 单盘和多盘项目卡片。
- 待处理与历史分区。
- 盘面详情数据、缩略图回退和三语言。
- 打印机添加、默认设备、缺失预设状态。
- 快速切片确认、进度、取消及错误恢复。
- 键盘焦点、读屏名称和明暗主题。

### 12.5 真实文件回归

使用用户提供的“萨莫面具-布莱克.gcode.3mf”验证：

- 提取彩色项目封面和盘面图。
- 识别 1 个盘、4 种耗材、14 层和约 5 小时 5 分钟预计时间。
- 显示的预计扣减克数与当前 G-code 正向挤出算法一致。
- 导入、取消、重新导入和结算均不产生缓存唯一键错误或重复扣减。

## 13. 验收标准

- 用户能浏览按项目分组的打印记录，并查看每盘完整详情。
- 多盘文件不会只读取第一盘。
- 缩略图缺失不会阻止导入。
- 每盘独立结算，库存流水保持可追溯和可逆。
- 普通 `.3mf` 可以通过后台 Bambu Studio 完成切片，正常过程不打开 GUI。
- 不兼容、失败或取消的切片不创建脏记录或半成品输出。
- 旧用户数据和备份可以无损升级。
- 三语言、明暗主题及基本无障碍交互完整。
- 全部自动化测试、生产构建、Rust 格式检查和 macOS `.app` 打包通过。
