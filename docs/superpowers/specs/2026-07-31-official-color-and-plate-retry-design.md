# CYLUNE 官方颜色身份匹配与单盘重打设计

## 目标

CYLUNE 必须保留拓竹官方耗材目录中的正式色号，同时可靠识别 3MF、Bambu Studio 和 AMS 可能保存的近似显示色。打印失败或取消后，用户可以直接为当前盘建立重打任务，不需要再次上传或切片整个文件。

## 官方颜色数据

- `src/catalog/bambu.json` 继续由 Bambu Studio 2.8.0.50 自带的 `filaments_color_codes.json` 生成。
- 官方色号、五位颜色代码、耗材型号、中文名称和多色顺序不因某个 3MF 的显示色而改变。
- 目录更新脚本保持可重复运行；生成结果必须确定且经过全目录完整性测试。
- 已添加的实体卷继续保存 `catalog_id`，它是比显示色十六进制值更稳定的官方颜色身份。

## 3MF 颜色归一与实体卷匹配

匹配按以下优先级执行：

1. 完整预设、材质、系列和颜色完全一致。
2. 机器无关的预设基础名与官方颜色完全一致。
3. 在相同官方预设基础名中，将 3MF 显示色解析到唯一且足够接近的官方目录颜色，再使用 `catalog_id` 匹配已装载实体卷。
4. 对缺少 `catalog_id` 的旧实体卷保留受阈值保护的近色回退。
5. 无法唯一确认时不自动声明“完全匹配”，要求用户选择。

颜色归一只能在相同耗材型号内进行，不能把 PLA Basic 的近似色匹配到 PLA Matte、PETG 或其他系列。渐变和多色卷以目录记录中的全部颜色参与身份解析，但最终仍以唯一 `catalog_id` 选择实体卷。

所有官方目录颜色必须具有精确匹配测试；真实切片别名必须覆盖白、红、蓝、黄以及 `#FFFF00` 到 PLA Basic 黄色 10400 的案例。

## 零用量耗材

- 每盘预览只展示切片结果中实际用量大于浮点容差的工具。
- 3MF 中存在但被 Bambu Studio 映射为零用量的耗材不要求实体卷匹配，也不参与扣减。
- 不修改 3MF 保存的耗材映射。例如保存为 `1 1` 的双色项目仍按 Bambu Studio 的实际单色切片结果记录。
- 如果一盘完全没有正用量工具，导入失败并返回稳定错误，避免产生无法结算的空任务。

## 失败或取消后的单盘重打

当用户以“打印中途失败”或“打印取消”完成当前盘结算后，CYLUNE 显示一次重打确认：

- “重新打印”：从解析缓存建立只包含当前盘的新打印项目并立即打开。
- “暂不重打”：保留当前结算结果，不创建新任务。
- 完整成功、按百分比估算和跳过不显示该确认。

新任务继承：

- 原始文件名和来源哈希；
- 当前盘的模型缩略图、层数、时间和各颜色用量；
- 原任务已经确认的工具到实体卷映射。

新任务拥有新的项目、盘和任务 ID，不复制任何结算、扣减或账本事件。它只包含失败或取消的当前盘，不重新创建同一 3MF 的其他盘。

## 幂等与历史

- `print_jobs` 保存可空的 `retry_of_job_id`，指向产生本次重打的已结算任务。
- 同一个来源任务最多创建一个直接重打任务；重复点击或请求重试返回同一个任务，不生成重复记录。
- 新的重打任务如果再次失败或取消，可以再产生下一代重打任务，形成可追踪的重打链。
- 原任务继续显示原本的失败或取消结果；新任务独立出现在待处理记录中。
- 删除未结算的重打任务只删除该新任务，不影响来源任务的结算和账本。

## 交互和错误处理

- 重打确认只在耗材扣减及数据库提交成功后出现。
- 创建成功后直接打开新任务；继承映射可供用户确认或更换，但不会再次要求上传文件。
- 创建失败时保留原结算结果并显示稳定错误，绝不撤销已经正确记录的本次用量。
- 忙碌期间禁用重复操作。

## 测试与发布

- Rust：官方目录身份解析、机器无关预设、真实颜色别名、歧义拒绝、零用量过滤、单盘重打、映射继承、账本隔离和幂等。
- React：失败/取消后显示确认；成功、估算和跳过不显示；确认后打开新任务；拒绝后停留在结果页。
- 真实回归：长弓文件不再显示或扣减零克黄色；官方黄色别名能够匹配 10400；多盘重打只生成当前盘。
- 完成所有功能后统一运行全量测试、生产构建、macOS 打包和签名验证。
